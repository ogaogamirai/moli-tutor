# 学習プロトコル v0.1（実運用で磨く前提の草案）

> **これは生きた草案です。** 実際に使いながら「重い／軽い／効く／効かない」を記録し、改訂していきます。
> 対象: moli-tutor を使った空き時間学習（**15分 / 1トピック**。時間があれば複数セット）。
> ゴール: **自分の言葉で説明できる**レベル。
> 改訂履歴は末尾。変えたら v0.1 → v0.2 …と上げ、変更点を残す。

---

## 0. 前提

- 学習者＝キャプテン。AI＝伴走（各家のチャット側）。moli-tutor＝場（教材＋学習マップ＋操作）。
- **低負荷が原則**: AIは教材全文を読まない。**DAGノードの要約＋`act`で指した箇所の前後**だけを使う。
- 解説はする。ただし**講義はしない**（1回 2〜3文＝100〜200字）。

## 1. 1トピックの型（15分）

**ループ（理解するまで繰り返す）**

1. **解説**（いまの深さで 2〜3文）＋ `act` で該当箇所を指す
2. **確認**（1問）
3. 判定して分岐:
   - 自分の言葉で言えた → **1段深く**（L0→L1→…）→ 1 へ
   - あいまい／誤り → **1段浅く**（分解・具体例・比喩に）→ 1 へ
   - 骨子も通らない → **さらに浅く**（L0を最小単位に割る）→ 1 へ
4. **合格したら次へ**（同じ深さの確認を繰り返さない）

**定着（最後2分）**

- 今日の到達を1行（復習テキスト）／次回の入口を決める。

## 2. 深度の階段

| 深さ | 何を言うか | 例（トロピカル半環） |
|---|---|---|
| **L0 骨子** | 一言＋構成 | 「⊕は“小さい方を選ぶ”、⊗は“足す”。この2つで経路の計算ができる」 |
| **L1 仕組み** | どう動くか | 「経路を伸ばす＝足す、合流＝小さい方を選ぶ、と読み替える」 |
| **L2 例** | 具体で確かめる | 「2⊕3=2、2⊗3=5」 |
| **L3 境界** | 成り立たない時 | 「引き算（逆元）が無い＝半環。だから割り算ができない」 |
| **L4 接続** | 他概念とつながる | 「ZDD/最短路と同じ“半環を差し替える”発想につながる」 |

**鉄則: 詰まったら深さを上げず、下げる。** 理解できたら1段上げる。

## 3. 塩梅（確認に時間を取られないノウハウ）

- **1解説＝1問**。質問攻めにしない。
- **確認は「関門」だけ**: 骨子の後／深さを上げる時／区切り前。
- **軽い確認**（「ここまでで引っかかる所ある?」）と**重い確認**（「自分の言葉で言うと?」）を使い分け。重いのは**深さを上げる時だけ**。
- **合格＝自分の言葉で言えた**。完璧は求めない（**8割で次へ**）。
- **同じ所を3回浅化しても通らない → いったん置く**（`fragile` として記録し、次回 fade-out で戻る）。
- **1ノードの質問は3〜5問まで**。**15分を超えたら区切る**。

## 4. AIの規律（コンパクト）

- 1ターン＝短い解説（2〜3文）＋1問。長文にしない。
- 教材の朗読・コピペをしない。指すのは `act`（左ペインのハイライト）。
- 詰まったら**深さを下げる**。「もう一度説明する」は同じ深さの繰り返しではなく、**浅く**やり直す。
- 進んだら `status` の「現在ノード」を更新（ノードの status）。

## 5. 道具の使い方（moli-tutor）

```bat
REM 準備（教材ごとに一度）
python -X utf8 tutor_cli.py add-material "<URL/PDF/HTML>" --material-id <id>
python -X utf8 tutor_cli.py dag "materials/<id>/index.html" --material-id <id> --pack packs --state tutor_state.json
python -X utf8 tutor_cli.py open --material-id <id> --pack packs

REM 各ターン
act.bat --heading-index <n>        REM 該当箇所を指す
act.bat --scroll-to "<語>"          REM 語をハイライト
python -X utf8 tutor_cli.py status  REM 現在地・進捗を読む（AIが低負荷で）
```

- 学習マップ（右ペイン上部）をクリックしても該当見出しへ飛べる。
- 区切り: 復習1行＋次の意図（daily に1行）。

## 6. データ（実装予定）

- `dag` の各ノードに **`depth`（0–4）** と **`fragile`（bool）** を持たせる（どこまで掘ったか／置いた所）。
- 保存先は `packs/<material_id>/dag.json`（`status`／`load` が読み書き）。

## 7. 改訂の作法（living document）

1. 学習の後、**1行の気づき**を残す（どこで詰まった／塩梅が合わなかった所）。
2. 数セッションごとに §3 塩梅を見直す。
3. 変えたら版を上げ、末尾に変更点を書く。

## 8. 未決（使って決める）

- 「8割で次へ」の線引き（厳しめ／緩め）。
- `fragile` の扱い（自動で fade-out に回すか、手動か）。
- 1ノードの質問上限（3〜5問のどこか）。

## 9. v0.2 候補（2026-10-13 初回試行の気づき）

- **テンポ**: 問いをその場で作ると遅い。→ **Phase 0 でノードごとに問いを先に用意（質問バンク）**し、本番は選ぶだけにする。
- **問いの設計**: 「なぜ×→＋」のような**こちらが作った前提の問い**は不正確になりやすい。**キャプテンの直感（つなげる＝足し算）を先に引き出す**問い方へ。
- **浅化の実例**: L1で詰まったとき「5分＋4分」の具体で通った → 浅化の型として有効。
